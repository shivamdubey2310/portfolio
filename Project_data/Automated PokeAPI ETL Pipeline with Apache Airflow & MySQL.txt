Automated PokeAPI ETL Pipeline with Apache Airflow & MySQL

Overview
An end-to-end data pipeline orchestrated with Apache Airflow that extracts complex hierarchical API data, transforms it, and loads it into a normalized MySQL relational database.

Tech Stack
- Orchestration: Apache Airflow (DAGs)
- Language: Python (Pandas, SQLAlchemy)
- Database: MySQL
- Source: External REST API (PokeAPI)

The Challenge
Public APIs often deliver data in deeply nested, semi-structured formats (JSON) that are incompatible with analytical tools requiring structured formats. The challenge was to systematically flatten this data while preserving complex relationships (e.g., Many-to-Many mappings between entities) and automating the update process.

The Solution
I developed a modular DAG (Directed Acyclic Graph) in Airflow to manage the lifecycle of the data:
- Complex Transformation: Wrote custom Python logic to parse nested JSON arrays, handling "One-to-Many" relationships (e.g., Pokemon to Abilities) and mapping them to a strict relational schema.
- Automated Workflow: Defined Airflow tasks for Extraction, Transformation, and Loading, enabling daily automated runs with built-in retry mechanisms and dependency management.
- Relational Design: Architected a normalized MySQL schema (pokemon, species, abilities) to ensure data integrity and minimize redundancy.

Key Highlights
- Semi-structured to Structured: Demonstrated the ability to convert NoSQL-style JSON data into a clean SQL schema.
- Robust Error Handling: Implemented logging and modular task design to ensure pipeline reliability.
- Container Ready: Designed the workflow to be compatible with Dockerized Airflow environments.
